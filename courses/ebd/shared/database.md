# Your database

The back end needs one file, **`backend/.env`**: the address and password of your database on Atlas, from Lab 5. Find your row:

| You have | Go to |
|---|---|
| The `.env` from your Lab 5 project, or `atlas-credentials.env` in your Downloads | <Link to="db-copy">**Put your .env in backend**</Link> (1 slide) |
| An Atlas account, but not that file, or you forgot its password | <Link to="db-login">**Log in to Atlas**</Link> (3 slides) |
| No Atlas account | <Link to="db-signup">**Sign up**</Link> (6 slides) |

Not sure you have an account? Try to log in at [cloud.mongodb.com](https://cloud.mongodb.com) with your email. **Forgot password?** there emails you a reset link. No email from MongoDB, ever? Sign up.

# Log in to Atlas (1 of 3)

1. Go to [cloud.mongodb.com](https://cloud.mongodb.com) and log in with the email you signed up with. Signed up with Google? Use **Google** instead.
2. Forgot your password? **Forgot password?** on the login page emails you a link to set a new one.
3. Atlas emails you a code (the multi-factor authentication from Lab 5). Type it in.
4. You see your project, with **Cluster0** on it. No cluster at all? Make one on <Link to="db-deploy">**A free cluster**</Link>, and carry on from there.

<div class="giu-refs__note">There are <strong>two</strong> passwords. Your <strong>Atlas password</strong> logs you in to this website. Your <strong>database user's</strong> password is the one your server uses, and the one that goes in <code>.env</code>. Next, you make a new one of those.</div>

# New password (2 of 3)

1. In the sidebar, **Database & Network Access** → **Database Users**. Your user is listed, for example `yourname_db_user`. That is your database **username**.
2. On its row, click **Edit**.
3. **Edit Password** → **Autogenerate Secure Password** → **Copy**. Paste it in Notepad for now: you need it on the next slide.
4. Click **Update User**.
5. Still under **Database & Network Access**, open **IP Access List**. `0.0.0.0/0` must be there, **Active**. Not there? Add it as on <Link to="db-ip">**Every IP address**</Link>, then come back.

<div class="giu-refs__note">Use the autogenerated password, not one you make up: a <code>@</code>, <code>:</code> or <code>/</code> in it breaks the connection string. The old password stops working now.</div>

# Make your .env (3 of 3)

1. In VS Code's Explorer, in `backend`, create a file named `.env`, next to `server.js`.
2. In Atlas, sidebar **Clusters** → **Connect** on Cluster0 → **Drivers**. Copy the connection string it shows: it starts with `mongodb+srv://`.
3. In `.env`, type `MONGODB_URI=""` and paste the string between the two quotes.
4. Replace **`<db_password>`**, the `<` and `>` too, with the password from Notepad. If it also says `<db_username>`, replace that with your username. Save.

`.env` is one line, and looks like this:

```ini
MONGODB_URI="mongodb+srv://yourname_db_user:Xk29fQp7LmZ3wR8d@cluster0.ab1cd.mongodb.net/?appName=Cluster0"
```

# Every IP address (4 of 5)

Atlas only lets in the IP address you had a minute ago. Your address at home is not your address at university, so allow them all.

![Atlas: IP Access List, with the menu entry and Add IP Address numbered 1 and 2](/img/screenshots/atlas-ip-list.png)

In the sidebar, **Database & Network Access** → **1** IP Access List · **2** + ADD IP ADDRESS

---

1. Type `0.0.0.0/0` under **Access List Entry**. It means "every address".
2. Click **Confirm**.
3. Wait until the new line says **Active**: about a minute.

<div class="giu-refs__note">Fine for a course project, never for real data: the password becomes the only lock.</div>

# Put your .env in backend

1. Find your file: `.env` in your Lab 5 project folder, next to `package.json`, or `atlas-credentials.env` in your Downloads.
2. Drag it onto the `backend` folder in VS Code's Explorer, so it sits next to `server.js`.
3. Called `atlas-credentials.env`? In VS Code, right-click it → **Rename**, to exactly `.env`.
4. Don't edit what is inside. It looks like this:

```ini
MONGODB_USERNAME="yourname_db_user"
MONGODB_PASSWORD="Xk29fQp7LmZ3wR8d"
MONGODB_URI="mongodb+srv://yourname_db_user:Xk29fQp7LmZ3wR8d@cluster0.ab1cd.mongodb.net"
```

<div class="giu-refs__note">On a Mac, Finder hides files whose name starts with a dot: press <strong>Cmd+Shift+.</strong> to see your Lab 5 <code>.env</code>. Rename in VS Code, not in Windows' File Explorer: it can hide the end of the name and make it <code>.env.env</code>.</div>

**Terminal → New Terminal**. This is **terminal 1**, the back end:

```bash
cd backend
npm install
npm run dev
```

Wait. Atlas is far away, so the second line can take a few seconds:

```text
Connecting to MongoDB...
Connected to MongoDB
Server running on http://localhost:3000
```

A red error instead? <Link to="fix-env">**The back end won't start**</Link> or <Link to="fix-db">**won't connect**</Link>, in Troubleshooting at the end. On the GIU network, a **phone hotspot** often fixes it.

::right::

**Terminal → New Terminal** again. This is **terminal 2**, the front end:

```bash
cd frontend
npm install
npm run dev
```

Open the `Local:` link it prints.

**Today both halves run**: keep both terminals open.
